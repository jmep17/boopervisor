Decision · 2026-09-02 ·proposed

Claude Code setup layout

Where machine config, personal plugins, forked third-party skills, and per-repo output declarations should live.

TL;DR

Recommendation: Four homes by lifecycle — it is the only layout where a forked skill survives updates, a new machine bootstraps with one command, and second-brain goes back to being a wiki. The options grid below carries the evidence.

Next → click the option you accept, or the one that contradicts the recommendation, and submit.

Context

The setup is spread across second-brain (a Karpathy-style wiki that also hosts the plugin marketplace, 20 project-scope skills, and the ADHD writing standard), a hand-edited ~/.claude, and unversioned ~/.agents skills — and it is already drifting: the two caveman copies differ, second-brain plan 044's edit to the improve plan template is gone from this machine, and the marketplace is registered by the local path /Users/jorden/second-brain. The trigger is wanting the same setup on a work machine plus ADHD-friendly forks of mattpocock/skills and shadcn/improve. Success: one bootstrap command per machine, personal edits version-controlled, each repo declaring its own output locations (the plan-018 pattern).

Option A

Four homes by lifecycle

  • +claude-setup (bootstrap + settings template), claude-plugins (marketplace + adhd plugin), GitHub forks of the two skill repos, and the 018 declaration in each repo — each piece changes at its own pace.
  • +Forks are real git repos: ADHD edits survive skills update and merge upstream with git merge — the exact failure that erased plan 044's template edit cannot recur.
  • +second-brain returns to being a wiki; work machines never need the personal knowledge base cloned.
  • −Four repos to maintain, and upstream merges into the forks stay manual.
  • −The bootstrap script must be kept honest or machines drift from it silently.
Option B

Everything in second-brain

  • +No new repos: marketplace, skills, and the ADHD standard already live there; add an install script and stop.
  • +One clone gives a machine everything at once.
  • −The wiki stays coupled to tooling: its 20 project-scope skills work only inside that repo, and the marketplace stays pinned to wherever it is cloned.
  • −A work machine must clone the entire personal knowledge base to get a plugin.
  • −Third-party forks still have no versioned home, so unversioned-edit loss continues.
Option C

One Claude monorepo

  • +Setup, plugins, and vendored skill copies in one repo: one clone, one bootstrap, atomic cross-layer changes.
  • +Simplest mental model — “my Claude repo” answers every where-does-this-go question.
  • −Vendoring loses git merge upstream: tracking mattpocock/skills and shadcn/improve becomes hand-copying diffs forever.
  • −The skills CLI and the plugin marketplace each want to own installation; a mixed repo fights both conventions.
Option D

Inside Boopervisor

  • +The product that edits Claude Code settings would dogfood its own domain, and a future settings panel is already a recorded direction candidate.
  • −Personal forks and machine config land in a shareable product repo — anyone cloning the app inherits your setup.
  • −Config changes ride the app's release cadence and test suite; editing a skill should not require a product PR.
  • −Boopervisor should manage the other homes through its UI, which it cannot do cleanly if it also is one.
Recommendation

Four homes by lifecycle. It is the only option that versions the forks, unpins the marketplace from a local path, and keeps both the wiki and the Boopervisor product single-purpose.

NoteMigration order, each step small: claude-plugins split → forks + one caveman scope → claude-setup bootstrap → the 018 declaration in boopervisor and second-brain.
NoteOnce the forks read ADVISOR_PLANS_DIR / ISSUES_DIR / ADR_DIR, plan 018 can shrink to “018-lite”: the env block, the CLAUDE.md table, two docs/agents/ files, and the agreement test — no guard hook.
RiskFour repos are four places to forget. The bootstrap script in claude-setup must be the only way a machine is configured; a hand-edited machine reintroduces the drift this layout exists to end.
OpenIf accepted: does 018 ship full (with the guard hook) or as 018-lite from the start?
