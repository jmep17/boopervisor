### Direction candidates from the frontend audit (not planned; available on request)

- **A theme choice (system / light / dark).** `globals.css:136-143` defines `.light` and
  `.dark` overrides and `docs/design-system.md:29` documents them, but nothing in the app
  ever sets either class — the switch exists in CSS only. A control in the header, persisted
  in a cookie the server layout reads (so the first paint has the right class and there is
  no flash), would deliver what the doc already describes. Trade-off: one more piece of
  Boopervisor-owned state; a cookie is fine for a local tool. Effort S.
- **Find-as-you-type on `/settings`.** 217 catalogued keys across 17 topics render on one
  page (`settings-list.tsx`) with no filter and no topic navigation. A `?q=` search param
  filtered server-side keeps the "state lives in the URL" convention and needs no client
  state; a sticky topic list would be the alternative. Trade-off: a filtered list must still
  show the "Settings files" section and the Uncatalogued section, or say why they are
  hidden. Effort S–M.
- **Wide-screen density on `/settings`.** At the 72rem container a row puts its key at the
  far left and its value at the far right; scanning is a long eye travel. Options: cap the
  list at `max-w-4xl`, or move the value beside the key with the badge trailing. This is a
  design call, not a bug; plan 008 fixes the overflow without choosing. Effort S.

### Found but not planned

- **`/history` diffs every record in the browser on load.** `history-list.tsx:14,41-48`
  ships the entire log — every mutation's full before and after text — to the client, and
  `history-row.tsx:40` runs `diffText` for each one during render, not on expand. The diff is
  an O(m×n) dynamic-programming table (`diff.ts:106-127`). **Measured, so the size is honest**:
  today's real log costs 0.28 MB and 2 ms across 390 records, which is nothing. Synthetic
  10,000-line inputs cost 600 ms and ~1 GB RSS for a single record. `~/.claude.json` is 1,856
  lines today, so the cliff is reachable but not close. Latent; worth pagination and a
  diff-on-expand change when `/history` next gets attention. The same page also makes 727
  sequential filesystem calls (73 ms measured) that could be one `Promise.all`.
- **A skill is keyed by its frontmatter `name`.** `skills/read.ts:127` writes
  `skills[metadata.name]`, so two skills whose SKILL.md declares the same name silently
  collapse into one and the loser vanishes from `/skills`. The disabling mechanism keys on
  that name too (`skillOverrides`), so there is no correct behaviour available without a
  design decision about which name wins. Small, but it needs that decision first.
- **`isValidationOk` (`config/validate.ts:108`) has no callers**, and the readdir loops in
  `skills/read.ts:119-133` and `plugins/read.ts:123-138` await one file at a time. Both are
  tidy-ups, neither is worth a plan on its own.
- `src/components/history/history-row.tsx:4` still imports `basename` from `node:path` in a
  client component (carried over from the previous run's list).

### Direction candidates from this audit (not planned; available on request)

- **Redact secrets in the history and in backups.** Every `before`/`after` is shipped to the
  browser and rendered as a diff, and settings `env` blocks and MCP server `env` maps are where
  API keys live. The catalog is the natural place to mark which keys carry secrets, and the diff
  renderer the natural place to mask them. Trade-off: a masked diff is a worse diff, and the
  backup on disk still holds the real value — plan 017's file modes are the cheaper 80%. Effort M.
- **Decide whether Boopervisor edits MCP server definitions at all.** `mcp-mutations.ts` was
  built to read-modify-write only the `mcpServers` key of `~/.claude.json` and was never wired
  up; plan 015 deletes it. The product question it leaves open — can a user add or edit a server,
  or only enable, disable and archive one? — is worth answering deliberately rather than by
  omission. `docs/PLAN.md` currently says item content is not edited, which argues for "no".
  Effort M if the answer is yes.

### `src/lib` findings considered and rejected

- **The catalog bloating the client bundle** — `settings.data.json` is 128 KB, but the three
  client components that import `@/lib/catalog` (`control-component.tsx`, `setting-row.tsx`,
  `hooks-editor.tsx`) take type-only imports, and `hooks-editor.tsx` imports the 24-line
  `catalog/hooks.ts`. Nothing pulls the data file into the browser.
- **Prototype pollution through `setAtPath`** (`config/paths.ts:41-58`) — a computed key in an
  object literal creates an own property, so `__proto__` cannot poison the prototype chain here.
- **Arbitrary project directories** (`scope/actions.ts:42-50`) — writing to
  `<any absolute directory>/.claude/settings.json` is the product's purpose, not a traversal bug.
- **No server-side confirmation for `dangerous` keys** — the confirmation dialog plan 006 added
  is a UX guard against a slip, not a security control, and a server-side token would add
  ceremony without a threat it addresses.
- **`readMutationLog` casting each parsed line to `MutationRecord`** — the log is a file
  Boopervisor wrote itself, malformed lines are already skipped, and a schema check would buy
  nothing a corrupt-line skip does not.
